# 🕊️ Freedom — чат со сквозным шифрованием: Android + веб + Python-сервер

Текст, фото, **голосовые** и **видеосообщения**, **аудио- и видеозвонки** (WebRTC), комнаты и личные чаты,
«печатает…», непрочитанные, push (FCM), история с подгрузкой. Клиенты: Android (Kotlin/Compose) и веб.
Между собой они полностью совместимы (звонок Android ⇄ браузер, голосовые и видео в обе стороны).
Сервер один, `contora.is-local.org`, и только по HTTPS; в клиентах адрес зашит, поля ввода сервера нет.
Есть настольные клиенты для Windows (`.exe`) и Linux (`.deb`, `.rpm`), их можно скачать на странице входа.

🔒 **Всё содержимое зашифровано сквозным шифрованием**: тексты, фото, голосовые, видео и сигналы звонков.
Сервер видит только шифртекст, публичные ключи и метаданные (кто, кому, когда). Протокол, гарантии и ограничения:
[E2EE.md](E2EE.md). Прочитайте раздел «Чего протокол не даёт» до того, как на это полагаться.

## 1. Сервер (только HTTPS, contora.is-local.org)

### Автоматически, на Debian/Ubuntu
    cd server
    # положите сертификат в certs/: certificate.crt, ca_bundle.crt, private.key — тогда установщик подхватит
    # их сразу; можно и позже, скрипт сам скажет, чего не хватает
    sudo bash install-debian.sh

Ставит системные пакеты (Python, venv, компилятор на случай отсутствия готового пакета под вашу архитектуру),
разворачивает код в `/opt/freedom`, создаёт отдельного системного пользователя `freedom` (без входа в систему),
виртуальное окружение со всеми зависимостями из `requirements.txt`, базу и загруженные файлы в `/opt/freedom/data/`,
и службу systemd — с непривилегированным запуском (`CAP_NET_BIND_SERVICE` вместо root) и песочницей
(`ProtectSystem=strict` и т.п.). Заодно ставит и настраивает **свой TURN-сервер** (`coturn`, для звонков через
мобильные сети и строгий NAT, см. §11) — тоже как отдельную, включённую и запущенную службу systemd, с автоматически
определённым внешним IP (если сервер за NAT домашнего роутера) и секретом, который сохраняется между переустановками.
Порты 80/443/3478 и диапазон релея открывает в `ufw`, если он используется и включён.

Дальше:

    sudo systemctl status freedom     # состояние сервера
    sudo systemctl status coturn      # состояние TURN
    journalctl -u freedom -f          # логи сервера
    journalctl -u coturn -f           # логи TURN
    sudo bash install-debian.sh       # повторный запуск = обновление: код и зависимости обновляются,
                                       # база, файлы, сертификаты и секрет TURN не трогаются
    sudo bash install-debian.sh --uninstall           # убрать службу, данные и сертификаты оставить
    sudo bash install-debian.sh --uninstall --purge   # + стереть данные, сертификаты и пользователя

Другие полезные флаги: `--host` (другой домен вместо `contora.is-local.org` — не забудьте поменять его и в
клиентах, см. ниже), `--dir` (другой путь вместо `/opt/freedom`), `--no-turn` (без своего TURN, только
публичный STUN), `--turn-secret` (задать секрет TURN самому, а не генерировать), `--no-start` (подготовить
всё, но не запускать), `--help` — полный список. Скрипт не трогает сеть за пределами `apt`/`pip` и определения
внешнего IP для TURN (сертификаты не запрашивает и никуда не отправляет) и безопасен для повторного запуска.
Проверено без root/apt/systemd (какие проверки требуют реального Debian с сетью и когда скрипт запускался
по-настоящему — в комментарии в конце `tests/server/install_script_test.py`); полный цикл на целевой машине
стоит один раз прогнать глазами по выводу.

### Вручную, на других системах
    cd server
    python -m venv .venv && source .venv/bin/activate   # Windows: .venv\Scripts\activate
    pip install -r requirements.txt
    # положите сертификат в server/certs/: certificate.crt, ca_bundle.crt, private.key (chmod 600 private.key)
    python serve.py --check     # проверка сертификата без запуска
    sudo -E .venv/bin/python serve.py

- Сервер слушает **443 (https)**, а порт **80 только перенаправляет** на `https://contora.is-local.org` (`HTTP_PORT=0`
  отключает перенаправление, `PORT` меняет порт https). Открытого http нет: HSTS включён, CSP разрешает только `wss`.
- Порты 80 и 443 требуют прав: `sudo`, либо `sudo setcap 'cap_net_bind_service=+ep' $(readlink -f .venv/bin/python)`
  (именно так и делает служба systemd, которую ставит `install-debian.sh`).
  Проверьте, что 80 и 443 проброшены с роутера на этот компьютер и открыты в файрволе, а `contora.is-local.org`
  указывает на ваш внешний IP.
- `serve.py` сам собирает цепочку (`certificate.crt` + `ca_bundle.crt`, без промежуточного сертификата часть клиентов
  отвергнет сервер), проверяет ключ, имя и срок, и **не запустится** с негодным сертификатом. Закрытый ключ не
  входит в архив проекта: файлы сертификата вы кладёте сами (папка `certs/` исключена из git).
- **Сертификат ZeroSSL действует до 20.12.2026** (90 дней). Продлите заранее, замените три файла в `certs/` и
  перезапустите сервер; за 14 дней до срока `serve.py` предупреждает. Если в новом `ca_bundle.crt` другой промежуточный
  сертификат, замените и `app/src/main/res/raw/zerossl_intermediate.crt` (см. раздел про Android).
- Другое имя сервера: переменная `CHAT_HOST` (и `SERVER_URL` в приложении Android, `SERVER_ORIGIN` в десктопе).
- Для разработки без TLS: `uvicorn main:app --port 8000` (клиенты Android и десктоп с ним не работают: они принимают
  только https).
- `freedom.db` и `uploads/` создаются рядом (`CHAT_DB`, `CHAT_UPLOADS` меняют пути).
- **Обновления сервера базу не ломают** — при старте сервер сам доводит схему до нужной версии, ничего не
  теряя (пользователи, сообщения, реакции, закрепления и т.д.), и снимает резервную копию файла базы перед
  первым же изменением схемы (`freedom.db.backup-v<N>` рядом с самой базой — можно удалить после того, как
  убедились, что всё на месте). Единственное исключение — совсем старые базы, ещё домиграционные (раньше
  версии 7, когда сообщения хранились открытым текстом): такие сервер по-прежнему просит удалить руками вместе
  с `uploads/` и завести всё заново — переносить нешифрованную историю в зашифрованную схему не станем.

## 2. Веб-версия
Открывается по адресу **https://contora.is-local.org** (`server/web`: index.html, style.css, icons.js, e2ee.js, app.js,
downloads.js; сборка не нужна). Шифрование, микрофон, камера и звонки работают только на HTTPS, что здесь
обеспечено. Ключи в браузере хранятся в IndexedDB как неизвлекаемые. Интерфейс приходит с сервера, поэтому
оператору сервера придётся доверять; подробности в E2EE.md.

Оформление сделано в духе Telegram Desktop/Web: линейные SVG-иконки вместо эмодзи (`icons.js`), пузыри сообщений
со скруглением и «хвостиком» у последней реплики в пачке, сообщения одного автора подряд группируются (аватар
и имя — только у первой реплики пачки), круглые аватары с цветом по хэшу имени, поиск по чатам в сайдбаре,
разделители дат, светлая и тёмная тема (следует системной). Десктоп-клиент показывает этот же интерфейс, так что
редизайн общий для веба и десктопа; экран звонка и просмотр фото/видео остаются тёмными в обеих темах — как в
большинстве мессенджеров. Android получил тот же визуальный язык: свой набор линейных SVG-иконок вместо эмодзи в
шапке, меню и composer'е (`Icons.kt`, те же контуры, что в `icons.js`, собраны через `PathParser`, а не
`material-icons-extended` — этой зависимости нет в проекте), круглые аватары с цветом по хэшу имени (`Avatar` в
`Common.kt`, общий для списка чатов и шапки чата), «хвостик» у пузыря сообщения, скруглённое поле ввода. Экран
звонка не трогал — он и так был ближе к веб-стилю (стеклянные круглые кнопки), не хотелось тратить риск непроверяемых
правок на то, что не выглядело крудо на скриншотах.

## 3. Приложение Android
1. Откройте корень проекта в Android Studio (Koala или новее, JDK 17), дождитесь синхронизации Gradle.
2. Запустите на устройстве или эмуляторе (**Android 8.0+**). Поля сервера нет: приложение работает только с
   `https://contora.is-local.org` (константа `SERVER_URL` в `ApiClient.kt`).
3. Имя приложения: **Freedom**, applicationId: `com.freedom.chat`.

Открытый http запрещён на уровне платформы (`res/xml/network_security_config.xml`). В доверенные якоря для
`contora.is-local.org` добавлен промежуточный сертификат ZeroSSL (`res/raw/zerossl_intermediate.crt`): так цепочка
проверится и на старых Android, где в системном хранилище нет корня Sectigo. Сессия и ключи, сохранённые прежней
версией приложения для другого сервера, при первом запуске стираются, нужно войти заново.

Ключи шифрования на устройстве защищены ключом Android Keystore. Вход и регистрация занимают несколько секунд
дольше обычного: из пароля выводятся ключи (PBKDF2, 310 000 итераций).

Разрешения запрашиваются по необходимости: микрофон, камера, уведомления (Android 13+). Во время звонка работает
foreground-сервис. Библиотека WebRTC: `io.getstream:stream-webrtc-android` (в `app/build.gradle.kts`); если Gradle не
найдёт версию, укажите актуальную с https://github.com/GetStream/webrtc-android.

Звонки — тот же mesh, что и в вебе (§11): `CallManager` держит отдельное `PeerConnection` на каждого участника,
общие микрофон и камера просто добавляются в каждое; экран звонка показывает сетку плиток (видео или аватар с
именем, если видео ещё не пошло) на всех, кроме случая ровно одного собеседника — тогда как раньше, во весь
экран. Кнопки звонка в шапке чата теперь есть и в групповых чатах, не только в личных.

Во время звонка: звук идёт по приоритету Bluetooth-гарнитура → проводные наушники (разъём 3,5 мм) → динамик/
наушник телефона — переключатель «громкая связь» в этом случае не может перебить ни Bluetooth, ни провод
(обычные наушники Android и так подхватывает сам, но раньше явное включение динамика на видеозвонке всё равно
перебивало их — теперь нет); при поднесении телефона к уху в аудиозвонке (не в видео) гаснет экран — через
`PROXIMITY_SCREEN_OFF_WAKE_LOCK`; если система забирает звук другому звонку (например, ответили на обычный
вызов по SIM), Freedom сам глушит микрофон и показывает статус «На удержании», возвращая прежнее состояние
микрофона, когда звук возвращается.

Ответ, редактирование и удаление — по долгому нажатию на сообщение; вложение любого файла — отдельной кнопкой
рядом с фото в поле ввода (§5). Скачанный файл сохраняется в системную папку «Загрузки» — это работает на
**Android 10 и новее**; на более старых версиях вместо этого покажется понятное сообщение.

Свой профиль (био и QR-код для добавления в контакты) — по тапу на имя пользователя в шапке списка чатов;
профиль собеседника и псевдоним для него — по тапу на имя в шапке чата (§6). Псевдонимы и черновики — в
`SharedPreferences`, только на этом устройстве.

Реакции, пересылка, закреплённые сообщения, поиск по истории, самоудаление, форматирование текста (включая
спойлеры), галочки прочтения и @упоминания (§7) — по долгому нажатию на сообщение (реакции/пересылка/закрепление),
значку поиска и разделу «Безопасность» (самоудаление) в шапке чата. Упоминания в тексте только подсвечены — без
перехода в профиль по тапу, в отличие от веб-версии; поиск ищет по уже загруженной истории, как и там же;
спойлер раскрывается тапом по всему тексту сообщения разом, а не по отдельному отрезку — Compose не даёт так же
просто попасть тапом в конкретный кусок текста, как это делает CSS в вебе.

Заглушить и архивировать чат (§8) — по долгому нажатию на строку чата в списке. Отложенная отправка (§9) —
кнопка-часы рядом с отправкой, время выбирается системными диалогами даты и времени Android; список и отмена —
по значку часов в шапке чата, когда есть хоть одно запланированное. Опросы (§10) — кнопка-график в поле ввода,
голосование тапом по варианту, повторный тап по своему же — снимает голос; создание — тот же диалог, что и в
вебе (вопрос и до десяти вариантов).

Каталог стикеров (§12) — кнопка в composer'е открывает лоток установленных паков (тап отправляет стикер как
обычное зашифрованное фото — тот же путь, что и для остальных изображений), «Каталог» в лотке — поиск по
названию, создание своего пака и просмотр чужого. Права такие же, как в вебе: добавлять/удалять стикеры и весь
пак целиком может только автор, установить/снять чужой — кто угодно.

Роли участников и каналы (§13) в Android пока нет вообще — сделано только в вебе (=десктопе); сервер уже
полностью поддерживает и то, и другое одинаково. Создать канал, посмотреть роли участников, повысить/понизить
или исключить кого-то пока можно только оттуда — существующие группы в Android продолжают работать как раньше
(писать может кто угодно). Если Android-пользователь всё же состоит в канале (например, вступил через веб) и
попробует написать туда, не будучи владельцем или администратором, сервер как обычно откажет — Android покажет
это как обычную ошибку сервера (`error` по WS), без специального объяснения про роли, но и без падения.

Компоновка экрана чата подчищена: раньше в шапке было 5 всегда видимых иконок, а перед полем ввода — ещё 4
(фото/файл/опрос/стикер), из-за чего само поле сжималось. Теперь в шапке остались только звонки, а поиск,
безопасность и запланированные сообщения — за «⋮»; вложения (фото/файл/опрос/стикер) — за одной кнопкой «+»
слева от поля ввода, тем же выпадающим меню, что уже использовалось для мьюта/архива и создания чата.

Видеосообщения — кружки, запись внутри приложения через CameraX, без системной камеры (раньше был Intent
`ACTION_VIDEO_CAPTURE`). Кадр обрезается до квадрата (1:1) уже на уровне захвата (`ViewPort`), одинаково и в
превью, и в самом файле — итоговое видео само по себе квадратное, кружком его показывает только отображение
(`Modifier.clip(CircleShape)`), ровно как это устроено в Telegram. Кнопка видео и голосового сообщения — одна
и та же: тап переключает режим (значок меняется голос↔видео, ничего при этом не отправляется и не пишется),
а держать — идёт запись в текущем режиме, отпустить — отправить, смахнуть влево от кнопки — отменить. Тап и
удержание различаются по времени (порог 200 мс) — это надёжно и тогда, когда палец не двигается вовсе,
потому что фаза ожидания порога устроена как гонка между таймаутом и отпусканием, а не просто «есть ли новое
событие движения». Реализовано вручную поверх `awaitPointerEventScope`, а не через `IconButton.onClick`, чтобы
не конкурировать со встроенным `clickable` за одни и те же события. Ограничение обрезки кадра: рассчитана на
портретную ориентацию (`Surface.ROTATION_0`) — экран приложения ориентацию не блокирует, но переворачивать
телефон посреди записи кружка никто в здравом уме не станет.

Версия приложения (`versionName` в `app/build.gradle.kts`) сверяется с сервером при каждом запуске — что из этого
получается, см. §17.

> Kotlin-код Android в этой сборке не компилировался (в среде разработки нет Android SDK). Его криптопримитивы
> повторяют проверенную Java-реализацию, но первую сборку и запуск нужно выполнить у себя. То же касается
> нового набора иконок (`Icons.kt`): контуры фигур пересчитаны вручную и перепроверены (совпадение размеров
> прямоугольников/окружностей с оригиналом на бумаге), но отрисовать их здесь и посмотреть глазами нельзя —
> при первой сборке стоит открыть экраны и свериться со скриншотами веб-версии. Особо стоит взглянуть на ответ
> и редактирование сообщений (§5), а также QR-код в профиле (§6) — построчный перенос уже проверенного веб-кода
> (`Qr.kt` из `server/web/qr.js`), но сам Compose-рендер через `Canvas`/`drawRect` никто не видел. Ещё один
> большой пакет изменений без проверки — §7 целиком (реакции, пересылка, закрепление, поиск, самоудаление,
> форматирование, галочки, упоминания): разметка сообщений через `AnnotatedString`/`SpanStyle` в этом коде
> используется впервые, а автодополнение @упоминаний определяет место вставки по концу строки, а не по позиции
> курсора (обычное текстовое поле Compose здесь хранит только строку, без выделения/курсора) — рабочий, но более
> грубый способ, чем в вебе. И следом ещё один — §8–§10 (заглушить/архивировать, отложенная отправка, опросы):
> при переносе `PollCard` в код случайно затесалась чужая аннотация `@Composable`, оторванная от `ReactionsRow` —
> заметил и исправил сам, но это тот самый класс ошибок, который здесь в принципе не проверить иначе, кроме как
> компиляцией; выбор даты/времени для отложенной отправки — через системные `DatePickerDialog`/`TimePickerDialog`
> Android, а не что-то самописное, но и это никто не запускал. И самый большой такой пакет — §11 (групповые
> звонки): `CallManager` переписан с одного `PeerConnection` на карту `peerId → PeerConnection` с общими
> микрофоном/камерой на все, сетка плиток на экране звонка (`LazyVerticalGrid`) — это ровно тот код, для
> которого WebRTC-стек нужен по-настоящему (в отличие от QR или разметки текста, где логика проверяема и без
> компиляции), и здесь его не было и не могло быть. Аудио-маршрутизация (Bluetooth/провод/динамик) не
> трогалась — перенесена без изменений, она и раньше не зависела от числа участников. И последний на сегодня —
> §12 (каталог стикеров): скачивание и кэширование картинок на диске по id — простой код, без шифрования, ниже
> риском, чем остальное в этом списке, но `AsyncImage` (Coil) грузит их с диска только после `produceState`,
> а сама сетка стикеров (`FlowRowStickers`) — самодельная раскладка по строкам без экспериментального
> `FlowRow`, тоже никем не запускалась. И самый рискованный на сегодня — видеосообщения-кружки: CameraX
> (`RoundVideoRecorder`) здесь используется впервые за весь проект, а ручной жест «держать/смахнуть» поверх
> `awaitPointerEventScope` — код того рода, который либо работает как задумано, либо не собирается вовсе,
> без промежуточных состояний, и здесь его никто не запускал и не мог запустить. Особо стоит проверить первым
> делом: действительно ли `videoRecorder.start()` в `RoundCameraPreview` успевает вызваться до того, как
> палец могут отпустить (очень быстрый жест теоретически может попасть в состояние «камера ещё не привязана»
> — код на этот случай рассчитан, `stop()`/`cancel()` для непривязанной записи просто ничего не делают вместо
> падения, но повторится ли это на практике или оно не будет никогда достигнуто — вопрос уже к реальному
> устройству). Кнопки видео и голоса потом объединили в одну с переключением по тапу — добавилась ещё одна
> гонка корутин (`withTimeoutOrNull` вокруг `awaitPointerEvent` — ждём либо порог 200 мс, либо отпускание,
> смотря что раньше), которую тоже никто не запускал: логика рассчитана так, чтобы работать и когда палец
> вообще не двигается (обычные pointer-события приходят только при движении), но именно этот случай —
> тап без единого движения — сложнее всего проверить на бумаге, не запустив на устройстве. Последнее на
> сегодня — аватары: `AvatarCache` (обычный OkHttp-запрос с заголовком авторизации, без Coil-заголовков) и
> расширенный `Avatar()` с `produceState`-подобной загрузкой файла — простой код по образцу уже проверенных
> мест (стикеры, EncryptedImage), но тоже пока никем не запускался; уже находил у себя в этом же заходе один
> задвоенный `@Composable` при похожей правке (RoomRow, ещё раньше) — при правке `Avatar()` поймал такой же
> дубль сам, сразу после написания, так что конкретно это исправлено, но сам факт, что паттерн повторяется,
> стоит держать в уме при следующих похожих правках. Последнее — кнопка «Распознать текст»: сам запрос к
> серверу (`ApiClient.transcribe`) и чтение расшифрованного файла — простой код по уже проверенным путям
> (тот же `mediaFile()`, что и для воспроизведения), но ни разу не запускался; по-настоящему в этом заходе
> проверен только HTTP-слой на сервере — там, где это вообще было возможно без сети.

## 4. Как это работает (кратко)
- **Пароль → два секрета.** Из пароля на устройстве выводятся `auth` (уходит на сервер как «пароль») и `kek`
  (остаётся на устройстве). Приватные ключи хранятся на сервере только зашифрованными `kek`, поэтому с любого нового
  устройства достаточно ввести пароль. **Пароль нельзя восстановить**: забыли пароль, значит, история потеряна.
- **Ключ комнаты.** У каждой комнаты и личного чата есть общий ключ, выданный каждому участнику отдельным конвертом.
  Когда в комнату вступает новый участник, создаётся новый ключ, и он не читает то, что было до него.
- **Каждое сообщение подписано отправителем**, файлы шифруются блоками с отдельным ключом на файл.
- **Звонки:** SDP и ICE зашифрованы ключом двух собеседников, а сам звук и видео идут напрямую (DTLS-SRTP).
- **Проверка собеседника:** кнопка 🔒 в чате показывает номер безопасности. Сверьте его лично или по другому каналу.

Что сервер по-прежнему знает: имена, состав комнат, время и размер сообщений и файлов, факты и длительность звонков.
Push-уведомления содержат только имя отправителя (или название комнаты) и «🔒 Новое сообщение».

## 5. Ответы, редактирование, удаление, файлы, черновики
- **Ответ на сообщение.** Цитата (кто, что) кладётся внутрь зашифрованного сообщения — сервер её не видит,
  как и всё остальное содержимое. При ответе на уже отредактированное или удалённое сообщение цитата всё равно
  останется прежней (это снимок на момент ответа, не живая ссылка).
- **Редактирование.** Только текстовые сообщения и только автор. Сервер проверяет авторство по имени
  отправителя (само сообщение прочитать не может), сохраняет отметку времени правки (`edited_ts` — метаданные,
  как и время отправки) и рассылает всем участникам новый шифртекст. История хранит только последнюю версию —
  прежний текст нигде не остаётся.
- **Удаление.** «У себя» — сообщение пропадает только из вашей собственной истории (в базе появляется отметка
  «скрыто для вас», на других участников не влияет); можно для любого сообщения. «У всех» — только автор,
  строка стирается из базы безвозвратно вместе с приложенным файлом, остальным участникам приходит команда
  убрать её тоже. У «удалить у всех» нет ограничения по времени (в отличие от некоторых мессенджеров).
- **Файлы.** Помимо фото/голосовых/видео можно отправить файл любого типа и размера до 32 МБ — тем же
  постраничным шифрованием (E2EE.md, §5), с оригинальным именем внутри зашифрованного сообщения. Сервер
  видит только зашифрованный блоб, как и остальные вложения.
- **Черновики.** Недописанный текст сохраняется на устройстве при переключении на другой чат и
  восстанавливается при возврате; в списке чатов вместо последнего сообщения показывается «Черновик: …»
  (только у вас, серверу об этом ничего не известно). Между устройствами не синхронизируются.

Все пять пунктов реализованы и в веб-версии (а значит и в десктоп-клиенте, который её просто показывает), и
в Android — ответ и редактирование по долгому нажатию на сообщение, файл — отдельной кнопкой в поле ввода,
черновики — в `SharedPreferences`. Экран звонка не умеет отвечать/редактировать/удалять — там этому нет места.

Реакции, пересылка, закреплённые сообщения, поиск по истории, самоудаление, форматирование текста (включая
спойлеры), галочки прочтения, @упоминания, заглушение и архивирование чатов, отложенная отправка, опросы,
групповые звонки, каталог стикеров, роли участников и каналы — реализованы, см. §7–§13 (форматирование —
вводом `**`/`*`/`` ` ``/`~~`/`||текст||` вручную, без панели инструментов и WYSIWYG-редактора; опросы — только
одиночного выбора, без режима «викторина»; групповые звонки — mesh, до `MAX_CALL_PARTICIPANTS = 8` человек, без
SFU; стикеры — свой каталог паков, без импорта готовых извне; роли — owner/admin/member, в канале писать могут
только владелец и администраторы, см. §13). Из Telegram здесь по-прежнему сознательно нет: превью ссылок, ботов
и платежей — превью ссылок конфликтует с моделью приватности (пришлось бы кому-то сходить по URL), а боты и
платежи — категория функциональности, которой в архитектуре проекта попросту нет (им бы понадобилась своя
инфраструктура — исполнение стороннего кода, финансовые операции — а не только доработка уже существующей
модели комнат и ролей).

## 6. Публичный профиль, псевдонимы, QR-код, аватар
- **Профиль.** «О себе» — до 200 символов, открытый текст. В отличие от ключей шифрования (видны только тем, с
  кем есть общая комната), профиль — публичный по замыслу: его видно по одному имени пользователя, ещё до
  первого сообщения — так и задуман QR-код для добавления контакта (ниже). Само имя пользователя при этом тоже
  становится узнаваемым по этой ручке (что оно существует) — это и есть смысл «публичного», не случайная утечка.
- **Аватар.** Тот же принцип публичности, что и у био, и та же техническая модель, что у каталога стикеров
  (§12): картинка хранится на сервере открытым текстом, не через E2EE — шифровать нечем, это витрина, а не
  переписка. Загрузить/удалить свой аватар можно из профиля; до 2 МБ, JPEG/PNG/GIF/WEBP (проверка по
  магическим байтам, не по расширению из имени файла). При замене старый файл удаляется с диска, не копится.
  Виден везде, где сервер знает имя пользователя: в публичном профиле, в списке участников комнаты, в списке
  чатов — для личного чата это аватар собеседника, не свой. У кого аватара нет — показывается прежний цветной
  кружок с инициалом (хэш от имени), как и раньше.
- **Псевдоним.** Личная пометка вместо чужого имени — «Мама» вместо `ekaterina_p87` — видна только вам, только
  на этом устройстве, серверу неизвестна и между устройствами не синхронизируется (то же решение, что и для
  черновиков). Применяется везде, где показывается имя собеседника: список чатов, шапка чата, подпись
  отправителя в группе, цитата в ответе.
- **QR-код.** Кодирует `frdm:u:<имя>` — отсканировавший сразу открывает личный чат с вами, как если бы вписал
  имя вручную. Свой собственный QR-энкодер (в проекте нет готовых библиотек для этого): при разработке дважды
  ловил в нём реальные баги через независимую проверку декодированием (OpenCV) — сначала маска накладывалась на
  служебные зоны матрицы, потом порядок коэффициентов многочлена Рида-Соломона оказался перепутан. После
  исправлений — 100% расшифровки на широком наборе случайных строк; та же проверка (`tests/web/qr_test.mjs`)
  теперь в общем наборе тестов. Реализация одна и та же в вебе (`server/web/qr.js`) и в Android (`Qr.kt`,
  построчный перенос, сверенный побитово с веб-версией) — оба **показывают** свой код, но **сканирование**
  умеет только веб-клиент (через `BarcodeDetector` браузера, с понятным сообщением, если браузер его не
  поддерживает); в Android-приложении можно только показать свой код, добавить контакт по-прежнему — вводом
  имени вручную.

Загрузка и смена аватара пока сделана только в Android (в профиле — кнопки «Добавить/Сменить фото» и «Удалить
фото»), в вебе и десктопе — только показ уже загруженного (список чатов, участники комнаты, профиль
собеседника), кнопки загрузки там нет. Картинка скачивается и кэшируется на диске отдельно от остального
приложения (`AvatarCache.kt`) — большинство мест, где рисуется `Avatar()` (список чатов, шапка чата, участники
группы), не имеют под рукой ViewModel, поэтому кэш работает по глобальному токену сессии, а не через
привычный путь с `vm.stickerThumbFile`-подобной функцией, как у стикеров.

## 7. Реакции, пересылка, закреплённые сообщения, поиск, самоудаление, форматирование, галочки прочтения, упоминания
Все восемь пунктов теперь есть и в Android — палитра реакций и остальные пункты по долгому нажатию на сообщение,
поиск и самоудаление — в шапке чата и диалоге «Безопасность» соответственно, упоминания — только подсветка и
автодополнение при вводе `@` в групповых чатах, без клика на профиль (в отличие от веб-версии).
- **Реакции.** Палитра эмодзи в меню сообщения; повторный тап тем же эмодзи снимает реакцию, другим — меняет.
  Зашифрованы так же, как обычные сообщения (своим ключом комнаты) — сервер видит только кто и когда
  отреагировал, не сам эмодзи.
- **Пересылка.** Текст пересылается как новое зашифрованное сообщение в комнате-адресате; файл — расшифровывается
  на устройстве (тот же кэш, что и для показа/воспроизведения) и заново шифруется под ключ другой комнаты.
  Отдельного «скопировать файл на сервере» эндпоинта нет и не нужно — шифрование и так только на клиенте.
- **Закреплённые сообщения.** Прав и ролей в комнатах в этом проекте нет вообще — закрепить или открепить может любой участник,
  как и удалить сообщение «у себя». Панель под шапкой чата показывает последнее закреплённое, с прокруткой к
  нему по тапу.
- **Поиск.** Только по уже загруженной истории текущего чата — сервер не может искать по зашифрованным
  сообщениям, а полнотекстовый индекс на клиенте не заводили. Скорее «набрать заново» неудобно, чем
  ограничение: история подгружается страницами, и самый частый случай — «это было недавно» — работает сразу.
- **Самоудаление.** Настраивается за чат: от часа до месяца или выключено. Работает «лениво» — сервер стирает
  просроченные сообщения не по расписанию, а при следующем обращении к чату (чтении истории или отправке),
  без отдельного фонового процесса.
- **Форматирование.** `**жирный**`, `__жирный__`, `*курсив*`, `_курсив_`, `` `код` ``, `~~зачёркнутый~~`,
  `||спойлер||` — без вложенности, разбирается на клиенте при отображении; в зашифрованном тексте как было, так
  и хранится. Спойлер скрыт до тапа (текст есть в DOM, просто закрашен тем же цветом, что и фон — не вырезан и
  не спрятан насовсем); раскрытие — только на время текущего показа, не сохраняется нигде и сворачивается заново
  при следующей перерисовке.
- **Галочки прочтения.** Одна — отправлено, две (синие) — прочитано; используют то же поле `last_read_id`,
  что и счётчик непрочитанных, просто сервер раньше не рассылал его изменение другим участникам — теперь
  рассылает (`read_state` по WS). В групповом чате двойная галочка появляется, только когда сообщение прочли
  **все** участники, а не первый попавшийся.
- **@упоминания.** Только в групповых чатах (в личном — упоминать больше некого). Автодополнение по списку
  участников комнаты (`GET /rooms/{id}/members`, кэшируется на клиенте) при вводе `@`; `@имя` в тексте — обычный
  клиентский разбор, как и остальное форматирование (§7), сервер никакого отдельного поля для упоминаний не
  хранит и никого не уведомляет по-особенному — push у всех сообщений одинаковый (см. E2EE.md, §8).

## 8. Заглушить и архивировать чат
Обе настройки — только на этом устройстве (localStorage), как псевдонимы и черновики: серверу вообще не известны,
между устройствами не синхронизируются. Открываются через «⋮» на строке чата в списке (виден при наведении).
- **Заглушить.** Подавляет всплывающее браузерное уведомление о новом сообщении для этого чата (само сообщение
  приходит и учитывается в непрочитанных как обычно — заглушение касается только уведомления). Заглушённый чат
  помечен маленьким перечёркнутым колокольчиком рядом с именем.
- **Архивировать.** Чат пропадает из основного списка и переезжает в счётчик «Архив (N)» внизу — разворачивается
  по тапу, показывая архивные чаты вперемешку с обычными; вернуть обратно — тем же «⋮» на архивной строке.

## 9. Отложенная отправка
Кнопка-часы рядом с полем ввода (появляется вместе с кнопкой отправки, когда есть текст) открывает выбор даты
и времени — не раньше текущего момента, не дальше месяца вперёд. Панель под шапкой чата «Запланировано: N»
показывает список и позволяет отменить любое до наступления времени.

Только текст — файл на момент планирования ещё не обязательно выбран и зашифрован, а откладывать сам процесс
загрузки усложнило бы протокол непропорционально ценности функции. Видит и может отменить только автор: другим
участникам о существовании отложенного сообщения знать не положено, оно ничем не отличается от сообщения,
которое человек просто ещё не написал — даже собеседнику в личном чате сервер не подтвердит, что оно вообще
существует (`DELETE .../scheduled/{id}` отвечает 404, не 403, если сообщение не ваше).

Технически: текст шифруется сразу, в момент планирования (под текущую эпоху ключа комнаты) и лежит на сервере
как обычный шифртекст с меткой времени отправки — расшифровать его раньше срока сервер не может так же, как не
может прочитать обычное сообщение. Отправляет — фоновая задача, проверяющая раз в 10 секунд, не наступило ли
время у кого-нибудь из запланированных; появляется как самое обычное сообщение, ничем не помеченное. Задача
не висит постоянно с момента запуска сервера — стартует по требованию, при первом же запросе на планирование
где бы то ни было, и дальше живёт сама.

## 10. Опросы
Кнопка-график в поле ввода открывает создание опроса: вопрос и от двух до десяти вариантов ответа. Голос —
одиночного выбора (без множественного и без режима «викторина» с правильным ответом), повторный тап по своему
же варианту снимает голос. Результаты видны сразу всем участникам — доли в процентах и число голосов на каждый
вариант, свой выбор подсвечен рамкой.

Технически опрос — не отдельная сущность на сервере, а обычное сообщение: вопрос и варианты лежат внутри
зашифрованного содержимого, как текст обычного сообщения. Голос устроен так же, как реакция (§7) — своя
зашифрованная запись на пару «сообщение, участник», переголосование заменяет прежний выбор: сервер видит, кто
и когда проголосовал, но не за какой вариант — это решает каждый клиент самостоятельно, расшифровав голоса тем
же ключом комнаты, каким расшифровывает сами сообщения.

## 11. Звонки: STUN/TURN, групповые звонки
Звонок в личном чате — как и раньше, вдвоём. Звонок в **групповом** чате приглашает всех участников комнаты
разом (кроме того, кто звонит); каждый принимает или отклоняет по отдельности, и звонок продолжается для
оставшихся, даже если кто-то один отклонил или вышел — пока остаются хотя бы двое. Личный звонок — по сути
тот же механизм с одним приглашённым: сервер их не различает.

Технически — mesh, не SFU: каждый участник соединяется напрямую с каждым (DTLS-SRTP, `RTCPeerConnection` на
пару), сервер по-прежнему только пересылает зашифрованный сигналинг (SDP/ICE) и медиа вообще не видит — та же
модель приватности, что и для звонков вдвоём. У mesh есть цена: соединений растёт как N×(N−1)/2, поэтому размер
группового звонка ограничен (`MAX_CALL_PARTICIPANTS = 8` в `server/main.py`) — для честной видеоконференции на
десятки человек нужен отдельный медиа-сервер (SFU), пересылающий потоки централизованно; здесь его сознательно
нет, это отдельный, гораздо больший проект и означал бы уйти от «сервер не видит медиа». Кто первым предлагает
`RTCPeerConnection`-оффер, а кто просто отвечает, определено однозначно: новый участник всегда сам обзванивает
уже присутствующих, не наоборот — так у обеих сторон нет сомнений, чья очередь.

По умолчанию используется публичный STUN Google, этого хватает в одной сети и за простыми NAT. Для мобильных
сетей и строгих NAT нужен **TURN**; он видит только зашифрованный трафик.

**`install-debian.sh` ставит и настраивает свой TURN (`coturn`) автоматически** — на той же машине, как отдельную
службу systemd (`systemctl status coturn`), с секретом в `/opt/freedom/environment` (переживает переустановки) и
самостоятельно определённым внешним IP (`external-ip` в `/etc/turnserver.conf`), если сервер сидит за NAT
домашнего роутера — это как раз типичный случай для адреса вида `*.ddns.net`. Порт 3478 (UDP и TCP) и диапазон
релея 49152-65535 (UDP) при этом нужно **пробросить с роутера**, как и 80/443 (см. §1). Отключить: `--no-turn`.

Если ставите вручную (без `install-debian.sh`) или на другой системе — `apt install coturn`, пример
`/etc/turnserver.conf`:

    listening-port=3478
    min-port=49152
    max-port=65535
    fingerprint
    use-auth-secret
    static-auth-secret=ДЛИННЫЙ_СЕКРЕТ
    realm=contora.is-local.org
    external-ip=ВАШ_ВНЕШНИЙ_IP/ВАШ_ВНУТРЕННИЙ_IP   # только если сервер за NAT; иначе не указывайте
    no-multicast-peers
    no-cli

Сервер Freedom выдаёт клиентам временные логин и пароль автоматически:

    export TURN_URLS="turn:contora.is-local.org:3478?transport=udp,turn:contora.is-local.org:3478?transport=tcp"
    export TURN_SECRET="ДЛИННЫЙ_СЕКРЕТ"
    sudo -E .venv/bin/python serve.py

## 12. Каталог стикеров
Открытый (не E2EE) общий каталог — пак создаёт любой пользователь, содержимое видно всем, это витрина, а не
переписка (тот же уровень публичности, что у профиля/био, §6). Кнопка со стикером в поле ввода открывает лоток
уже установленных паков — тап по стикеру отправляет его в чат как самое обычное зашифрованное фото (тот же
`sendMedia`, что и для остальных изображений — шифрование самого сообщения каталог никак не касается). Кнопка
«Каталог» в лотке открывает поиск по названию пака и создание своего.

Пак создаёт и наполняет стикерами только его автор; удалить свой стикер или весь пак целиком может тоже только
он. Установить себе (или снять) чужой пак может кто угодно — своё авторство при этом не переходит. Лимиты:
до 2 МБ на стикер, до 120 стикеров в паке, до 30 паков от одного пользователя — разумные потолки против спама,
не более того.

**Импорта готовых паков из Telegram или других платформ здесь сознательно нет.** Полный набор стикеров чужого
пака физически доступен только через Bot API (нужен отдельный токен бота, свои условия использования) или
скрапинг публичной страницы пака — оба пути так или иначе означают обход или использование чужой платформы
способом, для которого она явно не давала разрешения на массовое копирование. К тому же подавляющее большинство
существующих стикерпаков построено на чужих персонажах или является самостоятельным произведением других
авторов — импорт стал бы инструментом обхода авторских прав, а не только технической интеграцией. Каталог здесь
наполняют только сами пользователи приложения — собственными картинками, с однозначным авторством.

## 13. Роли участников и каналы
Группа теперь не полностью симметрична: у комнаты есть автор (`owner`), он может назначать и снимать
администраторов (`admin`), переименовывать комнату, исключать участников и передаёт владение автоматически,
если выходит сам (сначала админу, если такого нет — самому давнему участнику). Администратор может переименовать
комнату и исключить рядового участника, но не владельца и не другого администратора — так один администратор
не может «захватить» комнату, договорившись с другим против третьего. Рядовой участник ничего из этого не
может, только выйти сам.

**Канал** — тот же механизм с одним отличием: писать (сообщения, файлы, отложенная отправка) может только
`owner`/`admin`, остальные — только читать, реагировать и голосовать в опросах, но не публиковать. Это не
отдельная крипто-схема — комната шифруется тем же общим ключом, что и группа (см. E2EE.md, §3): подписчик
канала расшифровывает сообщения ровно как участник группы, разница только в серверной проверке прав при
публикации. Присоединиться к каналу можно так же, как к группе — через `/rooms/discover` (публичный) или по
приглашению.

Личные чаты роли не касаются вовсе — там переименование, исключение и выход через эти ручки не имеют смысла
и явно отклоняются (400).

Создать канал (не только группу) и выйти из чата/удалить его теперь можно и из Android, не только из веба:
в списке чатов кнопка «+» предлагает «Новую группу» и «Новый канал» по отдельности (раньше был только один
безымянный пункт «Новая комната», всегда создававший группу), а долгое нажатие на строку чата получило пункт
«Удалить чат»/«Выйти» рядом с мьютом и архивом. Для группы/канала это по-настоящему выход через `/rooms/{id}/leave`
(с подтверждением — действие необратимое без повторного вступления); для личного чата — просто скрытие у себя
на этом устройстве (тот же принцип, что у мьюта/архива: переписка у собеседника не трогается, сервер об этом
вообще не узнаёт). Веб-клиент этого по-прежнему не умеет — создать канал или выйти из чата там нельзя, только
Android получил обе возможности в этом заходе.

Автоматический общий чат «Общий», в который раньше попадал каждый зарегистрированный пользователь, убран
полностью — не только его создание при старте сервера, но и отдельный, ранее незамеченный вызов при
регистрации (`add_member(GENERAL_ID, ...)`), который добавлял туда новых пользователей независимо от того,
существует ли сама комната. У существующих баз он удаляется миграцией (v11→v12) вместе со всей своей историей;
эта проверка идёт сразу по id, `is_direct` и названию, чтобы не задеть чужую комнату, которую кто-то мог сам
назвать так же.

## 14. Распознавание речи (по желанию)
Единственное место во всём проекте, где сервер намеренно видит расшифрованное содержимое — и только его,
по явному запросу, ни разу не сохраняя. Кнопка «Распознать текст» под голосовым или видеосообщением
(своим или чужим) расшифровывает его на устройстве — тем же путём, что и для обычного воспроизведения — и
отправляет уже открытые байты на `POST /speech/transcribe` отдельным запросом, никак не связанным с самим
зашифрованным сообщением. Результат остаётся в памяти экрана на этом устройстве, пока он открыт; сервер не
хранит ни присланное аудио, ни текст — оба живут только на время одного запроса.

Это осмысленно только для сервера, которым управляет тот же человек, что им и пользуется, — поэтому выключено
по умолчанию и требует явного действия оператора, ровно как push и TURN, а не включено «из коробки» для всех,
кто поднимет свою копию:
1. На сервере: `pip install faster-whisper` (не входит в обычную установку — тяжёлая зависимость: ctranslate2
   и веса модели, сотни МБ) и системный `ffmpeg` (`apt install ffmpeg` — им распознавание декодирует
   `.m4a`/любой другой формат в PCM).
2. `sudo bash install-debian.sh --whisper-model small` (или любое другое имя модели faster-whisper —
   `tiny`/`base`/`small`/`medium`; чем больше, тем точнее и медленнее) — как и `TURN_SECRET`, значение
   переживает переустановки, флаг не нужно повторять на каждом запуске. Без `install-debian.sh` —
   `export WHISPER_MODEL=small` и перезапустить сервер.
3. Модель загружается один раз, лениво, при первом запросе (не при старте сервера) — первый вызов после
   перезапуска будет заметно медленнее следующих.

Без настройки эндпоинт отвечает понятной ошибкой (503), а не пытается загрузить несуществующую модель.
В Android это сделано; в вебе и десктопе кнопки «Распознать» пока нет — сервер уже готов её принять.

## 15. Push-уведомления (по желанию)
1. https://console.firebase.google.com → проект → «Добавить приложение Android», имя пакета `com.freedom.chat`.
2. Скачайте `google-services.json` в папку `app/`. Пока файла нет, сборка проходит, push отключены.
3. Project settings → Service accounts → «Generate new private key».
4. Ключ подхватывается `install-debian.sh` сам, если положить `firebase-adminsdk.json` рядом со скриптом
   (в `server/`) перед установкой, — либо явно: `--firebase-credentials /путь/к/ключу.json`. Без
   `install-debian.sh` — `export FIREBASE_CREDENTIALS=/путь/к/ключу.json` и перезапустите сервер (в логе:
   «FCM включён»). Ключ, единожды скопированный в `$INSTALL_DIR/firebase-adminsdk.json`, остаётся там и
   подхватывается заново при каждой последующей установке сам — флаг не нужно повторять; убрать push можно,
   только удалив этот файл из `$INSTALL_DIR` вручную (обычная переустановка его не трогает).

Push приходит на свёрнутое или закрытое приложение: о сообщениях и о входящем звонке. Сервер не знает текста,
поэтому в уведомлении только «🔒 Новое сообщение».

## 16. Клиенты для компьютера (Windows и Linux)
Проект `desktop/` (Electron) собирается в установщики: **`.exe`** для Windows, **`.deb`** и **`.rpm`** для Linux.
Готовые файлы кладутся в `server/downloads/`, и на странице входа веб-версии появляется блок «Приложение для
компьютера» с кнопками «Скачать» (своя система подсвечивается, есть команды установки и SHA-256):

    cd desktop && npm install && npm run dist:linux     # .deb и .rpm
    npm run dist:win                                     # .exe (на Windows)
    npm run publish:local                                # копирует в ../server/downloads

Установщики в этой поставке **не собраны**: для сборки нужны интернет и Node.js. Проще всего GitHub Actions
(`.github/workflows/desktop.yml`). Подробности, установка у пользователей и устройство клиента: `desktop/README.md`.
Версия (`version` в `desktop/package.json`) сверяется с сервером при запуске и по кнопке «Справка → Проверить
обновления» — что из этого получается, см. §17.

## 17. Версии и обновления клиентов
У сервера и у каждого клиента своя версия: `APP_VERSION` в `server/main.py`, `versionName` в
`app/build.gradle.kts` (Android), `version` в `desktop/package.json` (десктоп). Веб-версия отдельной версии не
имеет: страница всегда приходит с сервера свежей, обновлять там нечего.

**Как выложить установщик.** Файл кладётся в `downloads/` (во множественном числе, рядом с `serve.py`; при
установке через `install-debian.sh` — `$INSTALL_DIR/data/downloads`, либо путь из `CHAT_DOWNLOADS`), и имя
должно совпадать с `Freedom[-_]…\.(exe|deb|rpm|apk)`, с номером версии `X.Y` или `X.Y.Z` внутри — например,
`Freedom-5.1.apk`. Остальное сервер молча пропускает. Чтобы Android-приложение предложило обновление, версия в
имени должна быть **строго выше** `versionName` собранного приложения. Проверить, что сервер файл видит:
`curl https://<сервер>/api/downloads`. Кнопку «Скачать» для Android на странице входа рисует `downloads.js`
(раньше для `.apk` там не было своей записи, и такой файл, уже верно отданный API, на странице молча
пропускался — исправлено и закреплено тестом). В Android в шапке списка чатов есть кнопка «Проверить
обновления» — в отличие от автоматической проверки, она не молчит и говорит, что именно увидело приложение
(свою версию, найден ли `.apk` на сервере, разобрался ли номер версии в его имени).

**Как это работает.** Android и десктоп-клиент при каждом запуске спрашивают сервер (`GET /api/ping` — версия
сервера и минимально поддерживаемая версия клиента; `GET /api/downloads` — версия последнего опубликованного
установщика для этой платформы, тот же список, что показывает страница входа) и сравнивают с собственной
версией:
- **Вышла версия новее** — необязательное, закрываемое уведомление (полоса сверху списка комнат в Android,
  диалог в десктопе) со ссылкой на скачивание с сервера. Отклик «Позже» запоминается на устройстве до
  следующей версии — повторно не надоедает, пока не выйдет ещё более новая.
- **Версия ниже той, что сервер ещё обещает поддерживать** — обязательное обновление: в Android это отдельный
  экран, перекрывающий всё приложение (в том числе экран входа), в десктопе — диалог при каждом запуске без
  возможности отключить его насовсем. Кнопка «Скачать» открывает установщик из `/downloads/` в браузере;
  на Android это обычная установка «из неизвестных источников» (система один раз спросит разрешение для
  браузера, как при любой установке APK не из Play Store).

**Как задать минимально поддерживаемую версию.** По умолчанию не задана — тогда клиентам только советуют
поставить более новую версию, если она есть в `server/downloads/`, а обязательных обновлений не бывает.
Поднимайте её при выпуске несовместимых изменений (протокола или самого клиента) переменными окружения сервера:

    export MIN_CLIENT_VERSION_ANDROID="5.0"
    export MIN_CLIENT_VERSION_WINDOWS="1.1.0"
    export MIN_CLIENT_VERSION_LINUX="1.1.0"

**Чтобы клиенты увидели новую версию**, соберите установщик (десктоп: `npm run publish:local`; Android: соберите
APK и положите в `server/downloads/` как `Freedom-<версия>-android.apk`, версия — 2 или 3 числа через точку,
например `5.1` или `1.2.3`) и перезапустите сервер, если меняли `MIN_CLIENT_VERSION_*`. Само содержимое версии
проверять не с чем сверять на сервере — он лишь сравнивает номера по имени файла, поэтому имя должно точно
совпадать с этим форматом (см. `server/downloads/README.txt`).

## Форматы и лимиты
| Тип | Android отправляет | Браузер отправляет | Лимит |
|---|---|---|---|
| Фото | JPEG (сжатие до 1600 px) | JPEG / GIF | 32 МБ на любой файл |
| Голос | AAC .m4a | WebM/Opus или MP4 (Safari) | (сервер) |
| Видео | MP4 (системная камера, до 60 с) | WebM (VP8) или MP4 | 30 МБ на клиенте |
| Файл | любой тип «как есть» | любой тип, как есть | 32 МБ |

Сервер не видит содержимого файлов, поэтому формат не проверяет: он хранит непрозрачный `.bin` и отдаёт его как
`application/octet-stream` только участникам комнаты. Тип, оригинальное имя и ключ файла лежат внутри
зашифрованного сообщения.

## WebSocket `/ws?token=<token>`
Клиент → сервер:
- `{"type":"message","room_id":1,"epoch":2,"ct":"…","sig":"…"}`, `{"type":"typing","room_id":1}`,
  `{"type":"read","room_id":1,"message_id":42}`
- `{"type":"call_invite","room_id":5,"call_id":"uuid","video":true}` — приглашает всех участников комнаты разом
  (групповой звонок — просто больше одного приглашённого, см. §11)
- `{"type":"call_accept"|"call_reject"|"call_end","call_id":"uuid"}`
- `{"type":"call_signal","call_id":"uuid","to":7,"data":{"n":"…","c":"…"}}` (зашифрованный SDP/ICE, адресован
  конкретному участнику по его id — участников может быть больше двух)

Сервер → клиент дополнительно рассылает `message_edited` (`id`, `room_id`, `epoch`, `ct`, `sig`, `edited_ts`),
`message_deleted` (`id`, `room_id`), `reaction_set`/`reaction_removed` и `vote_set`/`vote_removed` (одинаковая
форма: `room_id`, `message_id`, `username`, для `_set` ещё `epoch`, `ct`, `sig`), `message_pinned`/`message_unpinned`
(`room_id`, `message_id`) и `autodelete_changed` (`room_id`, `seconds`) — все в ответ на соответствующие
REST-вызовы выше, всем участникам комнаты. И `read_state` (`room_id`, `username`, `message_id`) — в ответ на
клиентское `{"type":"read",…}` выше, всем остальным участникам комнаты (не самому отправителю).

Сервер → клиент: `message` (`kind`: `e2e` или `call`; `epoch`, `ct`, `sig`, `media`), `typing`, `rooms_changed`,
`keys_updated`, `error` (`code`: `stale_epoch`, …), `call_invite` (тем, кого пригласили; `group` — правда,
если приглашённых больше одного), `call_joined` (тому, кто только что принял: `participants` — кто уже в
звонке, `[{id, username}, …]`, каждого нужно самому обзвонить — см. §11), `call_peer_joined`/`call_peer_left`
(остальным участникам: `user_id`, `username` — кто присоединился или вышел, сам звонок при этом продолжается),
`call_signal`, `call_end` (`reason`: busy, declined, cancelled, no_answer, ended, connection_lost — звонок
закончился целиком, для всех).

Итог каждого звонка (длительность, пропущенный, отклонённый) сохраняется в чате сообщением `kind: "call"`;
его текст формирует сервер (это метаданные, они не шифруются).

`bash tests/run-all.sh` (нужны node 20+, python3 + пакет `cryptography`, JDK 17+): совместимость веб-модуля,
Python-эталона и Java/JCA; логика сервера; интеграция JS-клиента с кодом сервера; запуск по HTTPS (цепочка

(так однажды не хватило `CHAT_STICKERS` — сервис падал на «Read-only file system» под `ProtectSystem=strict`),
поведение без systemd — без root/apt полный цикл не прогнать, см. `tests/server/install_script_test.py`);
раздача установщиков и версий (в т.ч. .apk, MIN_CLIENT_VERSION_*); ответы, редактирование и удаление сообщений,
включая авторизацию («чужое не тронешь») и удаление файла при «удалить у всех» (tests/server/edit_delete_test.py);
публичный профиль — что он виден без общей комнаты, в отличие от ключей (tests/server/profile_test.py);
реакции, закреплённые сообщения и самоудаление, включая очистку осиротевших записей при удалении сообщения
(tests/server/social_test.py); галочки прочтения — рассылку остальным, но не себе, и что last_read_id только
растёт (tests/server/read_state_test.py); отложенную отправку — приватность (собеседник не видит и не может
отменить чужое, 404 а не 403), что до срока ничего не появляется и не рассылается, саму отправку по сроку и

заменяет прежний выбор, а не дублирует, и что удаление сообщения (в т.ч. по самоудалению) подчищает осиротевшие
голоса (tests/server/poll_test.py); групповые звонки — что приглашаются все, кроме занятых, что отказ или
выход одного не рушит звонок для остальных (пока остаётся хотя бы двое), что call_signal адресован именно

## Перед публикацией
Продление сертификата до 20.12.2026 (и перезапуск сервера); свой TURN; PostgreSQL и S3 вместо SQLite и локальных файлов при росте; несколько процессов uvicorn
потребуют Redis для рассылки по WebSocket и общего хранилища состояния звонков; независимый аудит протокола, если
на него будут полагаться всерьёз. Большие комнаты: новый участник получает эпоху с конвертом на каждого участника
(O(n)), для тысяч участников понадобится иная схема.
